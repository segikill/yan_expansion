# ADR-001: отдельное хранилище и рабочие вкладки

Статус: принято для 1.10.0.

## Контекст

Версия 1.9.0 хранит всю базовую сессию под ключом `maps_export_session_v2`. Overlay держит копию сессии в памяти и периодически записывает её целиком. Если фоновый парсер будет изменять тот же объект, одна из сторон может затереть более новые данные.

## Решение

- Базовая сессия остаётся в `maps_export_session_v2` без миграции.
- Очередь и состояние запуска хранятся в `maps_export_enrichment_job_v1`.
- Подробные результаты хранятся в `maps_export_enrichment_results_v1`.
- Объединение выполняется по `object_key` в момент экспорта.
- Карточки открываются в 1–4 настоящих неактивных вкладках, каждая вкладка переиспользуется.
- Фоновый контроллер не хранит критичное состояние только в глобальных переменных; очередь переживает остановку service worker.

## Последствия

Плюсы: совместимость с 1.9.0, возможность частичного экспорта, повтор только ошибок, простое добавление категорийных адаптеров.

Минусы: два набора данных нужно согласовывать при экспорте; полная запись карты результатов на каждом шаге потребует оптимизации при десятках тысяч объектов.

## Валидация

1. Браузерный unit-test `tests/detail_parser.test.html`.
2. Ручной smoke-test на 10, затем 100 URL.
3. Проверка паузы, закрытия worker-вкладки, перезапуска браузера и CAPTCHA.
4. Сравнение XLSX с базовой сессией: количество строк и `object_key` не должны измениться.
